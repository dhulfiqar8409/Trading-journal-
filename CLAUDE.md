# Darkpools: project instructions for Claude Code

Darkpools is a multi-user trading journal (Next.js 16 App Router, TypeScript strict, Prisma 7
with PostgreSQL through @prisma/adapter-pg, hand-rolled auth, Tailwind, Recharts, vitest,
Playwright). Read `README.md`, `docs/product-spec.md` and `deploy/README.md` before larger work.
`AGENTS.md` is generated by `next dev`; commit it with your work rather than fighting it.

## The one thing to remember

**Every push to `claude/trading-journal-aws-pnsmv4` deploys to production within about ten
minutes.** The Release image workflow builds and publishes the image, and the server
(`darkpools.deeapps.net`) pulls it on a five-minute timer. Real users and real trades live there.
Push only work that has passed the checks below. Migrations must be additive and transactional
(nullable columns or defaults; never `CREATE INDEX CONCURRENTLY`), because
`prisma/deploy-migrations.mjs` applies them inside a transaction on the live database.

## Commands

- `npm run lint`, `npm run typecheck`, `npm test` (vitest), `npm run build`: all must be clean.
- `npm run e2e`: Playwright smoke suite against a running production build with a local
  PostgreSQL (see README for the setup); set `E2E_SETUP_TOKEN` when `SETUP_TOKEN` is set.
- `npm run seed`: development sample data only; refuses to run in production.
- Local database: `prisma migrate dev` for new migrations; production uses the applier above.

## Conventions

- Pure logic lives in `src/lib/*` with unit tests next to it (`src/lib/__tests__`); pages and
  actions stay thin. Every server action and route handler re-checks the session and scopes
  queries by `userId`; admin actions call `requireAdmin()` server-side.
- Money and quantities use Decimal end to end; convert to numbers only at the UI boundary.
- Every chart has a "Show as table" twin; every page must work at 390 px wide with no
  horizontal scroll (the smoke test checks this).
- Green and red mean only P&L sign. The visual identity (Instrument Serif headings, JetBrains
  Mono figures, restrained indigo accent) is deliberate; keep it.
- No AI model names in code, comments, docs or commit messages.
- Do not modify `deploy/`, `.github/workflows/release.yml`, `Dockerfile`,
  `docker-entrypoint.sh` or `prisma/deploy-migrations.mjs` without understanding the
  deployment flow in `deploy/README.md`.

## Production layout (KCAL host, Ubuntu, 1 GB RAM, small disk)

- App: `/var/www/darkpools/current` (symlink to `releases/<digest>`), service `darkpools`
  (systemd, user www-data, port 3300, localhost only), env in `/var/www/darkpools/shared/.env`
  (root:www-data 640; DATABASE_URL, SESSION_SECRET, SETUP_TOKEN, APP_ORIGIN, UPLOAD_DIR).
- Updater: `/usr/local/bin/darkpools-update` from `darkpools-update.timer`; `--retry` re-attempts
  a build marked failed. Logs: `journalctl -u darkpools -f`, `journalctl -u darkpools-update`.
- nginx: `/etc/nginx/sites-available/darkpools` (HSTS, security headers, login rate limit,
  `/api/health` internal only) using the wildcard certificate `/etc/nginx/ssl/acm-cert.pem`,
  which expires 2026-12-17 and must be re-exported from ACM before then.
- PostgreSQL 18 on the host, database and role `darkpools`. Backups: `scripts/backup-db.sh`.
- Host access is through AWS Systems Manager (instance `i-043907bf2b99ed875`, us-east-1);
  port 22 is open to the internet from before this project and should be restricted.
- Other applications on the same host (`kcal`, `unical`, nginx blocks `deeapps`, `unical`)
  must not be touched.

## Security posture

Setup page gated by `SETUP_TOKEN` and disabled once a user exists; no self-registration; admin
creates users with one-time temporary passwords; login lockout per username-and-address and
per address; session version invalidates sessions on logout, password change, reset or
deactivation; `__Host-` session cookie in production; origin checks on state-changing route
handlers; uploads sniffed, capped, quota-limited and served only to their owner; share links
are tokenised and revocable. An independent review's findings were all fixed (see git history,
"Fix the security review findings").
